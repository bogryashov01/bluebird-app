2. NOTIFICATION SETTINGS — MAKE THEM FUNCTIONAL
==================================================

The current Notifications screen must allow
users to change and save supported preferences.

Main Bluebird supports:

GET /api/me/profile
PUT /api/me/profile

Existing fields:

notificationPrefs.mode
notificationPrefs.allChannels
notificationPrefs.emptyLegHomeAirport
notificationPrefs.departingFavorite
notificationPrefs.arrivingFavorite
notificationPrefs.queueUpdates
notificationPrefs.winningNotifications

Modes:
off, all, specific

Channels:
email, sms, both

Flight-specific channels may also be null.

Implement functional controls for:

- Flights from my Home Airport
- All Flights
- Queue Updates
- Flight Confirmations

IMPORTANT:

These settings control EMAIL/SMS preferences,
not native push delivery.

"All Flights" and "Specific Flights" are
mutually exclusive backend modes.

Queue Updates and Flight Confirmations
are channel selectors, not optional
on/off preferences.

Do not implement an unsupported "off"
value for queueUpdates or winningNotifications.

Use compact, understandable controls
that match the approved light design.

If a user selects SMS or Both,
respect the existing explicit SMS
consent and phone validation requirements.

Never enable smsConsent automatically.

Unsupported controls:

- International Flights
- Membership Updates
- Native push notifications

Keep them clearly unavailable.
Do not persist fake preferences.

==================================================
3. NOTIFICATION SAVING
==================================================

Preferences must persist.

On screen open:

- Fetch the authenticated profile.
- Hydrate current saved preferences.
- Show a small loading indicator if necessary.

On change:

- Update the UI.
- Save through the real profile API.
- Confirm successful persistence.
- Show a concise error if saving fails.

After saving:

- Re-fetch the profile.
- Verify the saved values are reflected.

Ensure preferences remain correct after:

- Navigating away and back
- Refreshing the screen
- Restarting the app
- Switching authenticated accounts

IMPORTANT:

PUT /api/me/profile is a FULL profile update.

Required fields include:

firstName
lastName
dob
gender
homeAirportCode
favoriteCityKeys

Preserve all required and unrelated fields.

Do not submit a partial preferences-only body.

Do not overwrite favorite airports,
SMS consent, or unrelated notification settings.

Avoid concurrent writes that overwrite each other.

If the profile is incomplete,
show a short actionable message
instead of submitting an invalid request.
