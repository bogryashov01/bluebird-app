BLUEBIRD MOBILE — IMPLEMENT MEMBERSHIP MOCK MODE

GOAL:
Enable development and testing of the complete
Bluebird Mobile Membership UI using local JSON data
that matches the real Production API response.

CURRENT SITUATION:

- Production API is configured.
- Production Clerk is configured.
- Replit Web Preview cannot authenticate because
  Clerk rejects the Replit origin with HTTP 400.
- Existing Production membership is Base / Active.
- We want to continue developing and testing the
  Mobile Membership experience without depending
  on Production Clerk in Replit Preview.

IMPLEMENTATION:

1. Add an explicit development-only membership mock mode:

   EXPO_PUBLIC_BLUEBIRD_MEMBERSHIP_DATA_MODE=mock

2. Keep the existing Production API mode:

   EXPO_PUBLIC_BLUEBIRD_MEMBERSHIP_DATA_MODE=production

3. Create a local JSON fixture for membership data.

4. First inspect the existing Mobile API types and
   available Production response examples.

5. Match the real /api/membership response schema.
   Do not invent additional API fields.

6. The fixture should represent an active Base
   membership using the existing verified response
   structure.

7. Connect the Membership screen to a data provider
   that supports both mock and production modes.

8. In mock mode, Membership reads the local JSON
   instead of calling /api/membership.

9. Keep the existing Production API integration
   unchanged.

10. Add a development-only way to open the
    Membership screen in Replit Web Preview
    without requiring a Production Clerk session.

11. This preview route must not create a fake
    authenticated session or fake authorization token.

12. The preview route must not call protected
    Production API endpoints.

13. Make the mock preview clearly identifiable
    with a visible "MOCK DATA" indicator.

14. Mock mode and unauthenticated preview access
    must be impossible in release/production builds.

15. Preserve all Production Clerk security checks.

16. Do not modify the backend, website,
    Production database, or Clerk Dashboard.

17. Do not create an EAS build or deployment.

18. Add tests verifying:
    - Mock fixture matches the existing schema.
    - Mock Membership screen renders correctly.
    - Production mode still uses the real API.
    - Mock mode cannot activate in release builds.
    - Preview access cannot expose protected
      Production data.

EXPECTED RESULT:

- Replit Preview can display Membership.
- Base membership is visible.
- Active status is visible.
- Membership navigation works.
- No Clerk HTTP 400 blocks the mock preview route.
- Production integration remains intact.
