BLUEBIRD MOBILE — SKIP THE LINE PASS MVP

PRIORITY: HIGH
MODE: BUILD / EXECUTE

GOAL:

Add Skip the Line Pass functionality to the
existing Bluebird Mobile Queue experience.

PRODUCT RULE:

Skip the Line Pass allows an eligible member
to bypass the regular flight queue and
immediately secure a seat on an eligible flight.

This is NOT simply higher queue priority.

The Mobile app must distinguish:

1. Join the Queue
2. Skip the Line Pass

SCOPE:

Bluebird Mobile ONLY.

Main Bluebird Website/API is READ-ONLY
for contract inspection.

Do not modify Main Bluebird code,
database, Clerk, production settings,
or payment provider configuration.

==================================================
1. INSPECT EXISTING IMPLEMENTATION
==================================================

Inspect the current Mobile implementation:

- Discover
- Flight Details
- Join Queue
- Queue Status
- Trips
- Membership
- Existing API client
- Existing Skip the Line references

If Main Bluebird source is accessible,
inspect it READ-ONLY to determine:

- Whether Skip the Line Pass exists
- How Pass ownership is represented
- How Pass availability is checked
- Whether Pass purchase is supported
- Whether Pass redemption is supported
- How seat confirmation works
- Whether a Pass is consumed after booking
- What happens if the flight is unavailable

Do not invent endpoints or backend behavior.

==================================================
2. FLIGHT DETAILS — TWO OPTIONS
==================================================

Add two clearly separated actions:

OPTION A:

Join the Queue

Description:
"Join the queue for a chance to secure
your seat."

Primary action:
"Join Queue"

Preserve the existing real Queue flow.

OPTION B:

Skip the Line Pass

Description:
"Skip the queue and secure your seat
instantly on eligible flights."

Use a premium white rounded card
with a subtle blue accent and
lightning icon.

Do not clutter the screen.

==================================================
3. MEMBERSHIP STATES
==================================================

Support three states:

A. NO ACTIVE MEMBERSHIP

Show:

"Skip the Line Pass"

"Available with Bluebird Membership."

Button:
"View Membership"

Navigate to the existing Membership screen.

Do not allow Pass redemption.

B. ACTIVE MEMBERSHIP — NO PASS

Show:

"Skip the Line Pass"

"Secure a seat without joining the queue."

Button:
"Get Skip the Line Pass"

Open a dedicated Pass details screen.

C. ACTIVE MEMBERSHIP — PASS AVAILABLE

Show:

"Skip the Line Pass Available"

Button:
"Use Skip the Line Pass"

Only enable actual redemption when
the backend confirms the member
has an available Pass and the
selected flight is eligible.

Do not infer Pass ownership from
membership status alone.

If the backend cannot confirm Pass
ownership, show an unavailable state
instead of assuming the user has one.

==================================================

- Circular back button
- Title: Skip the Line Pass

Content:

Lightning icon

"Skip the Queue"

Show a compact explanation:

Show:

==================================================
5. PASS REDEMPTION
==================================================

IMPORTANT:

Skip the Line Pass must NOT call
the regular Join Queue endpoint.

These are different operations.

If Main Bluebird has a supported
authenticated Pass redemption API:

- Validate membership
- Validate Pass ownership
- Validate flight eligibility
- Request Pass redemption
- Prevent duplicate submissions
- Wait for server confirmation
- Display the confirmed result
- Refresh Trips and Pass availability

If no supported redemption API exists:

- Do not simulate a real booking
- Do not consume a Pass locally
- Do not create a fake reservation
- Do not show "Booking Confirmed"
  in the authenticated live flow

Instead show:

"Instant booking is coming soon."

==================================================
6. DEVELOPMENT PREVIEW
==================================================

Provide a development-only preview
of the Skip the Line flow.

It must support:

- Member without Pass
- Member with Pass
- Pass unavailable
- Pass redemption loading
- Simulated successful seat confirmation
- Simulated redemption failure

Every simulated state must be
clearly labeled DEMO.

Demo mode must:

- Be disabled in production
- Never call mutation APIs
- Never create real bookings
- Never consume real Passes
- Never modify user membership
- Never appear in real Trips
- Never mix demo data with live data

Reuse existing Queue demo infrastructure
if available.
