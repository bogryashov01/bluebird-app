3. SESSION / TOKEN ARCHITECTURE
==================================================

Clerk must become the authoritative authentication/session provider.

For authenticated Bluebird API requests obtain a fresh Clerk session token
using Clerk's supported getToken() mechanism.

Send:

Authorization: Bearer <Clerk session token>

Do NOT implement:

- custom JWT generation
- custom refresh tokens
- permanent bearer-token storage
- a second authentication session

Use Clerk's supported Expo token/session persistence.

If SecureStore is required by the Clerk Expo integration, use the supported
secure token-cache pattern.

Preserve web compatibility where reasonably required by the existing project.

Do not expose session tokens in logs.

==================================================
4. PRODUCTION /api/me
==================================================

Connect authenticated viewer state to:

GET https://bluebirdjets.com/api/me

Important:
This endpoint intentionally also supports anonymous requests and returns HTTP
200.

Therefore:

HTTP 200 DOES NOT MEAN AUTHENTICATED.

The app must inspect:

isAuthenticated

Expected response shape:

{
  isAuthenticated: boolean;
  isAdmin: boolean;
  isConcierge: boolean;
  isMember: boolean;
  memberTier: "base" | "plus" | null;
  email?: string | null;
  firstName?: string | null;
  lastName?: string | null;
  isProfileComplete: boolean;
  needsPlanDecision: boolean;
  needsSignupPhone: boolean;
  impersonation?: null | {
    active: boolean;
    adminClerkUserId: string;
    adminEmail: string | null;
    targetClerkUserId: string;
    targetEmail: string | null;
    targetName: string | null;
  };
}

Do not treat /api/me as the full profile endpoint.

Do not invent missing fields.

8. AUTH / ROUTING STATE
==================================================

Integrate Clerk state with the existing Expo Router navigation.

Required high-level states:

A. Clerk loading
   → show existing safe loading/splash behavior

B. Signed out
   → auth/welcome flow

C. Clerk signed in, /api/me loading
   → authenticated loading state

D. Clerk signed in, /api/me returns isAuthenticated: true
   → use Bluebird server state for routing

E. Clerk signed in but /api/me returns isAuthenticated: false
   → treat as auth/API mismatch and fail safely

F. Session expired / invalid
   → return safely to signed-out state

Avoid redirect loops.
