GOAL:

Audit the CURRENT user-visible Bluebird Web Preview and eliminate cases where

This is NOT a redesign and NOT a broad architecture audit.

Focus only on user-visible data integrity.

==================================================
1. AUDIT VISIBLE PUBLIC/READ-ONLY SCREENS
==================================================

Inspect the currently reachable UI, especially:

- Discover List
- Discover Map
- Flight Details
- airport search/selectors
- Membership catalog / plan comparison
- any shared cards/components used by those screens

Identify visible values that look dynamic or factual but are still sourced
from:

- fixtures
- hardcoded demo data
- local prototype API
- generated/random values
- assumptions not present in the production response

Examples:

- flight counts
- seat counts
- aircraft type
- aircraft images
- pricing
- dates/times
- queue counts
- route information
- airport names
- coordinates
- membership prices
- membership features
- availability labels
- international fees
- badges such as Featured / Popular / Available
- fake statistics

Do not flag clearly static marketing copy unless it makes a factual claim
that conflicts with production data.

==================================================
2. CLASSIFY EACH FINDING
==================================================

For every finding classify it:

A — production-backed and correct
B — static product copy, acceptable
C — demo/mock value visible as if real
D — unavailable production field with proper unavailable/neutral UI
E — authenticated feature intentionally deferred to Stage 2+

Only C is a Stage 1.7 cleanup target.

Do not start implementing E items.

==================================================
3. FIX ONLY MISLEADING MOCK DATA
==================================================

For category C findings:

Prefer:

- real production value when already available
- neutral unavailable state
- hiding the unsupported value

Do NOT invent replacements.

Examples:

If aircraftType is null:

GOOD:
"Aircraft details unavailable"

BAD:
"Gulfstream G450" from a fixture

If production does not provide seat count:

GOOD:
hide it / neutral unavailable state

BAD:
"8 seats" from demo data

If production plan availability says buyNowEnabled=false:

GOOD:
purchase unavailable

BAD:
active Buy Now button using prototype behavior
