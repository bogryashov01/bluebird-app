BLUEBIRD MOBILE — RESTORE PERSONAL INFORMATION SCREEN

PRIORITY: HIGH

CURRENT STATUS

The user can now successfully authenticate with Clerk
and enter the Bluebird Mobile Home screen.

However, navigating to:

Profile → Personal Information

shows:

"Personal Information unavailable.
Your authenticated account details can’t be read
or edited in this preview. The supported Clerk
profile update flow is not available on this screen,
so no profile changes were requested."

This is a blocking issue for the mobile MVP.

GOAL

Make Personal Information display the real authenticated
user's existing profile data.

Investigate whether safe profile editing is supported
by the existing Main Bluebird API contract.

STRICT SCOPE

BLUEBIRD MOBILE ONLY.

DO NOT MODIFY:

- Main Bluebird Website
- Main Bluebird API
- Database
- Clerk configuration
- Production configuration
- Existing registration flow
- Existing onboarding flow
- Flight Details implementation
- CORS diagnostic implementation

Do not modify shared authentication or API transport
unless absolutely necessary and explicitly justified.

TASK 1 — INVESTIGATE

Inspect the existing authenticated profile flow.

Check the documented and already-used endpoints:

GET /api/me
GET /api/me/profile
PUT /api/me/profile

Determine which fields are available and which fields
can safely be updated using existing documented contracts.

Do not invent endpoints or request fields.

TASK 2 — DISPLAY REAL PROFILE DATA

Replace the unavailable placeholder with a proper
Personal Information screen.

Display supported fields such as:

- First name
- Last name
- Email
- Verified phone number
- Date of birth
- Gender
- Home airport
- Favorite cities

Only display fields that are actually supported by
the API response.

Handle optional or missing values honestly.

Do not show fake profile data.

TASK 3 — SAFE EDITING

Enable editing ONLY for fields with a verified,
supported update contract.

Use the existing authenticated Clerk request flow.

Never send a profile update automatically.

Require explicit user action to save.

Do not retry failed PUT requests automatically.

Do not overwrite unrelated profile fields.

If the update contract is uncertain, keep those
fields read-only and explain the limitation.

Never change Clerk identity fields through an
undocumented Main API endpoint.

TASK 4 — UX

Use the existing Bluebird Mobile design system.

The screen should include:

- Back navigation to Profile
- Clear field labels
- Loading state
- Readable error state
- Save button only when supported editable
  fields have changed
- Success feedback after confirmed save

Preserve existing bottom-tab navigation.

TASK 5 — ACCESSIBILITY

Investigate the React Native Web warning:

"Blocked aria-hidden on an element because
its descendant retained focus."

If the warning is caused by this screen or its
navigation transition, apply a small focused fix.

Do not globally disable accessibility features
or change unrelated navigation.

TASK 6 — VERIFICATION

Run TypeScript and focused tests.

Verify that:

1. Authenticated users can open Personal Information.
2. Real profile values are displayed.
3. Missing optional fields do not crash the screen.
4. No profile writes happen on screen load.

7. Existing registration and onboarding remain intact.

Do not claim real API verification unless observed
