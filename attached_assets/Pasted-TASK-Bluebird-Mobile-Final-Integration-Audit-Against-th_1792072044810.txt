POST /api/me/phone-verification/check

IMPORTANT FINDINGS FROM MAIN AUDIT:

1. Bluebird profiles are associated
   with Clerk User IDs.

2. Memberships are associated
   with Clerk User IDs.

3. GET /api/me may return HTTP 200
   with signed-out flags after
   an internal backend failure.

4. isMember=false does NOT mean
   that the user is new.

5. isProfileComplete=false does NOT
   prove that no profile row exists.

6. GET /api/me/profile may return
   an empty profile shell.

7. GET /api/me/profile can have
   database write side effects.

8. PUT /api/me/profile performs
   a profile upsert by Clerk ID.

9. Bluebird has a separate Quo PIN
   verification flow after Clerk signup.

10. The main audit could not verify
    whether the Quo PIN feature flag
    is enabled in the live runtime.
