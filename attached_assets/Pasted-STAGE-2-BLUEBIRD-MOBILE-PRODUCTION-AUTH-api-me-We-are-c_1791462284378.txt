==================================================
PHASE 5 — PRODUCTION /api/me
==================================================

Implement a small typed/validated production viewer client for:

GET https://bluebirdjets.com/api/me

For authenticated calls use the current session token:

Authorization: Bearer <current session token>

Do not log the token.

IMPORTANT:

/api/me intentionally may return HTTP 200 for anonymous users.

Therefore:

HTTP 200 != authenticated.

The response field:

isAuthenticated

must determine Bluebird backend authentication state.

Expected application-state fields include:

isAuthenticated
isAdmin
isConcierge
isMember
memberTier
email
firstName
lastName
isProfileComplete
needsPlanDecision
needsSignupPhone
impersonation

memberTier may be:

"base"
"plus"
null

Do not invent missing fields.

Do not treat /api/me as the full member profile endpoint.

==================================================
PHASE 6 — AUTH STATE MODEL
==================================================

The mobile app must distinguish:

1. Auth provider loading
2. Signed out
3. Signed in, /api/me loading
4. Signed in + /api/me isAuthenticated:true
5. Signed in + /api/me isAuthenticated:false
6. /api/me network/server failure
7. expired/invalid session

A successful auth-provider session alone must NOT mean Bluebird onboarding is
complete.

Use server application state:

isProfileComplete
needsPlanDecision
needsSignupPhone
isMember
memberTier

Do not invent membership or onboarding state locally.

Avoid redirect loops.
