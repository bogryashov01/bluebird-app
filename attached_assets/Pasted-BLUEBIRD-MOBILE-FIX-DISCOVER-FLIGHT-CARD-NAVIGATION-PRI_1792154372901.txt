BLUEBIRD MOBILE — FIX DISCOVER FLIGHT CARD NAVIGATION

PRIORITY: HIGH
TYPE: BUG FIX

CURRENT PROBLEM

The Flight Details implementation task was completed,
but the main user interaction does not work.

On the Discover / Home screen, the user sees
a list of published flights.

Example cards:

SAT → CXO
HEF → HUF
TTN → CYUL
GON → JVY

When the user taps any flight card,
nothing happens.

The user remains on Discover.

EXPECTED BEHAVIOR

Tapping a flight card must open the
Flight Details screen for that specific flight.

This must work in the actual Expo Web Preview,
not only in unit tests.

STRICT SCOPE

BLUEBIRD MOBILE ONLY.

DO NOT MODIFY:

- Main Bluebird Website
- Main Bluebird API
- Database
- Clerk authentication
- Registration
- Onboarding
- CORS diagnostics
- Profile screens
- Membership logic
- Production configuration

Do not redesign Discover or Flight Details.

TASK 1 — TRACE THE TAP

Inspect the actual flight card component rendered
on the Discover screen.

Determine:

1. Is the card a Pressable or Touchable component?
2. Is onPress attached to the actual visible card?
3. Does the handler execute when tapped?
4. Does it receive the correct selected flight?
5. Does navigation execute?
6. Is the Flight Details route registered?
7. Does the destination screen receive the flight ID?

Do not assume the component is connected
just because Flight Details exists.

TASK 2 — FIX THE NAVIGATION

Connect the existing Discover flight cards
to the existing Flight Details screen.

Use the navigation system already present
in Bluebird Mobile.

Do not introduce a second navigation system.

Pass a stable flight identifier or the selected
flight data using the existing supported pattern.

Do not hardcode flight information.

Every card must open its own corresponding flight.

TASK 3 — PRESERVE EXISTING UX

Keep the existing Discover design unchanged.

The entire flight card should be tappable.

The Back button on Flight Details must return
to Discover.

Preserve:

- Current flight list
- Search query
- List / Map selection
- Scroll position where supported
- Existing bottom-tab navigation

Do not trigger bookings, queue joins,
or membership actions when opening details.

TASK 4 — HANDLE MISSING DATA

If a flight does not have a usable identifier,
do not silently ignore the tap.

Display an appropriate unavailable state
or use an already-supported selected-flight
navigation contract.

Do not invent an API endpoint.

TASK 5 — REAL VERIFICATION

Run TypeScript and focused tests.

Verify the complete interaction:

Discover
→ Tap SAT → CXO
→ Flight Details opens
→ Correct SAT → CXO information appears
→ Back
→ Discover

Then repeat with another flight:

Discover
→ Tap HEF → HUF
→ Flight Details opens
→ Correct HEF → HUF information appears

IMPORTANT:

A test that directly renders Flight Details
does NOT prove that tapping Discover cards works.

Verify the actual card-to-screen navigation path.

If real Expo Web Preview interaction cannot be
performed, explicitly report that limitation.

FINAL REPORT

1. Root cause of non-working card taps
2. Files changed
3. Navigation fix implemented
4. How selected flight data is passed
5. Test results
6. Whether actual browser tapping was verified

Make the smallest possible Mobile-only fix.
