BLUEBIRD MOBILE — DEVELOPMENT PREVIEW MODE

PRIORITY: HIGH
MODE: BUILD / EXECUTE

GOAL:

Enable developers to preview and test
Bluebird Mobile screens without requiring
access to the production Clerk SMS account.

This is a DEVELOPMENT-ONLY preview system.

It must never bypass production authentication.

SCOPE:

Bluebird Mobile ONLY.

Do not modify Main Bluebird,
Clerk backend, database, or production.

==================================================
1. DEVELOPMENT PREVIEW
==================================================

Create a development-only screen preview system.

Allow developers to inspect:

- Discover
- Flight Details
- Queue
- Trips
- Membership
- Skip the Line Pass
- Profile
- Notifications
- Home Airport
- Payment Methods

No production Clerk session is required
for previewing simulated UI states.

==================================================
2. SECURITY REQUIREMENTS
==================================================

Development Preview must:

- Be unavailable in production builds
- Never create a real authenticated session
- Never generate or reuse Clerk tokens
- Never bypass backend authentication
- Never call protected APIs using fake identity
- Never mutate real user data
- Never create real queue entries
- Never create real bookings
- Never simulate payment success

Use local fixtures only.

==================================================
3. PREVIEW STATES
==================================================

Support:

Discover:
- Available flights
- Empty state
- Loading
- API error

Queue:
- Not joined
- Waiting
- Unavailable

Trips:
- Empty
- Queued flight
- Confirmed flight

Membership:
- Non-member
- Active member
- Loading
- Error

Skip the Line Pass:
- Non-member
- Member without Pass
- Member with Pass
- Unavailable

Profile:
- Complete profile
- Missing information

Notifications:
- Off
- All
- Specific

==================================================
4. DESIGN
==================================================

Reuse existing production screen components
where possible.

Do not build an unrelated mock application.

Keep the approved Bluebird design.

Display a clearly visible:

"DEMO / DEVELOPMENT PREVIEW"

indicator on all preview screens.

==================================================
5. NAVIGATION
==================================================

Allow developers to navigate between
preview screens.

Simulated actions must remain local.

Never redirect preview users into
real authenticated backend flows.

==================================================
6. RELEASE SAFETY
==================================================

Ensure preview code is inaccessible
in production builds.

Use compile-time development guards
where appropriate.

Verify release builds cannot activate
preview through URL parameters,
deep links, or hidden navigation.

==================================================
7. TESTING
==================================================

Run TypeScript and relevant tests.

Verify:

- Preview works without Clerk login
- Preview never uses real API tokens
- Preview never performs live mutations
- Preview is unavailable in production
- Existing real authentication is unchanged

==================================================
8. DELIVERY
==================================================

Implement directly.

Report:

1. How to open Development Preview
2. Screens available
3. Simulated scenarios
4. Security protections
5. Tests passed
6. Files changed

Do not modify Main Bluebird.
