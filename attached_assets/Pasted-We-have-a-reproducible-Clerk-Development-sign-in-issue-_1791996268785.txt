We have a reproducible Clerk Development sign-in issue.

Observed behavior:

1. User presses "Send verification code".
2. Clerk returns:
   verification_code_too_many_requests

3. The UI displays:
   "Could not prepare the code"

4. However, the phone owner receives an SMS verification code.

5. The UI remains on the phone-entry screen.

Previously, the missing phoneNumberId issue was fixed
in Task #376.

TASK:

Investigate the Clerk phone-code preparation lifecycle,
especially duplicate requests and SMS delivery timing.

Requirements:

1. Inspect all calls to:
   - signIn.create()
   - signIn.prepareFirstFactor()
   - signIn.attemptFirstFactor()

2. Determine whether a single button press can trigger
   multiple SMS preparation requests.

3. Check for:
   - React double submissions
   - Duplicate event handlers
   - useEffect-triggered requests
   - Automatic retries
   - Multiple prepareFirstFactor calls
   - Stale Clerk resources
   - Race conditions

4. Verify that signIn.create() and prepareFirstFactor()
   are not redundantly requesting the same SMS code.

5. Add safe Development-only diagnostics showing:
   - Request stage
   - Request count
   - Clerk response status
   - Clerk error code

6. Never log:
   - Phone numbers
   - SMS codes
   - Session tokens
   - Clerk secrets
   - Full API responses

7. Improve handling of Clerk rate limits.

8. Prevent duplicate submissions while a request

9. Display a useful cooldown message when Clerk
   returns verification_code_too_many_requests.

10. Do not automatically retry SMS requests.

11. Do not treat an HTTP error as successful verification

12. Preserve the working sign-up flow.

13. Add mocked regression tests for:

    - Duplicate button press

    - Rate-limited preparation

14. Run TypeScript and relevant authentication tests.

Report the exact cause if confirmed, otherwise list
