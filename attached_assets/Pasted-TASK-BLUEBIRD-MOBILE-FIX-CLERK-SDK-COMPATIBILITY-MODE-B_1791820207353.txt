TASK: BLUEBIRD MOBILE — FIX CLERK SDK COMPATIBILITY

MODE: BUILD / IMPLEMENTATION

PROJECT: Bluebird Mobile (Expo / React Native)

CONTEXT:

Task #339 confirmed that Clerk SDK cannot currently be
installed cleanly with the existing dependency baseline.

Current versions:

Expo: 54.0.37
React: 19.1.0
React Native: 0.81.5

Previously tested:

@clerk/expo@4.10.1
@clerk/expo@2.19.0

Both resolved transitive dependencies with React peer
requirements incompatible with React 19.1.0.

The older SDK also requires expo-auth-session.

GOAL:

Find and implement the smallest officially supported
dependency changes required to install @clerk/expo
without breaking Expo SDK 54.

IMPORTANT:

Do not upgrade Expo SDK or React Native major/minor
versions just to satisfy Clerk.

Do not use:

--force
--legacy-peer-deps
peer dependency overrides
package manager tricks to suppress incompatibilities

PHASE 1 — INVESTIGATE

Inspect:

- Root package.json
- Bluebird app package.json
- pnpm-workspace.yaml
- pnpm-lock.yaml
- Existing Expo dependency constraints
- React and React DOM versions
- Clerk SDK peer requirements
- Transitive Clerk package peer requirements

Determine the smallest compatible version combination.

Check Expo SDK 54 compatibility requirements.

Do not assume a successful dependency resolution
means the versions are compatible.

PHASE 2 — ISOLATED VALIDATION

Test candidate dependency combinations in an
isolated temporary worktree.

Do not modify the main working tree during probing.

Check:

1. pnpm dependency resolution
2. Peer dependency compatibility
3. Expo dependency validation
4. TypeScript compilation
5. Metro bundling
6. Existing authentication tests

If available, perform a native compatibility check.

Do not claim native compatibility based only on
successful Metro bundling.

PHASE 3 — IMPLEMENT IF SAFE

Only if a candidate passes the compatibility gates:

- Install the compatible @clerk/expo version.
- Install required Expo-compatible peer dependencies.
- Make only the minimum necessary React patch update,
  if officially supported by Expo SDK 54.
- Update the appropriate package.json files.
- Update pnpm-lock.yaml.

Do not mount ClerkProvider yet.

Do not replace AuthContext.

Do not connect production authentication.

Do not activate authenticated member screens.

If no candidate is demonstrably compatible,
do not change project dependencies.

Instead, report the exact blocker.

PHASE 4 — VERIFICATION

Run:

- pnpm install --frozen-lockfile
- Expo dependency validation
- Library TypeScript checks
- Bluebird application TypeScript checks
- Existing authentication API tests
- Existing startup regression tests
- Metro export/bundle verification
- git diff --check

Use the appropriate workspace commands.

PHASE 5 — REPORT

Provide:

1. Selected Clerk SDK version
2. React version
3. React Native version
4. Expo version
5. Installed peer dependencies
6. Exact dependency changes
7. Compatibility evidence
8. Tests and results
9. Remaining native verification requirements
10. Whether ClerkProvider can safely be integrated next

RESTRICTIONS:

Do not modify the main Bluebird backend.

Do not modify the local API server.

Do not add Clerk secret keys.

Do not perform production authenticated requests.

Do not send SMS.

Do not initiate payments.

Do not deploy.

Do not commit.

Do not push.

Do not modify existing UI or navigation.

Do not install dependencies unless compatibility
has been demonstrated in the isolated worktree.

SUCCESS CRITERIA:

A compatible Clerk SDK is installed with a clean
dependency graph, passing Expo checks, typechecks,
tests and Metro verification.

If this is not possible, leave the main project
unchanged and explain the smallest viable next step.
