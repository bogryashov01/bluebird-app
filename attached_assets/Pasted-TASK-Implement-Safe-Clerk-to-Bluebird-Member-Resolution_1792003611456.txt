TASK: Implement Safe Clerk-to-Bluebird Member Resolution

CONTEXT:

Task #394 is complete.

Bluebird Mobile now has:
- Clerk-only authentication
- A production API transport layer
- Fresh Clerk token retrieval
- Typed GET /api/me adapter
- Existing Registration, Onboarding and Home screens

The only intended backend is:

https://bluebirdjets.com/api

CURRENT BLOCKER:

After Clerk authentication, users remain on:

"Bluebird member not linked"

We need to connect Clerk authentication to
the existing Bluebird account system.

GOAL:

Clerk Session
    ↓
Bluebird Member Resolution
    ↓
Existing Member → Home
New Member → Registration → Onboarding → Home

IMPLEMENTATION:

1. Review the existing production API foundation
   from Task #394.

2. Implement a centralized member-resolution
   state machine with these states:

   - signed_out
   - resolving
   - linked
   - registration_required
   - onboarding_required
   - unresolved
   - error

3. Use the existing GET /api/me adapter.

4. Obtain fresh Clerk tokens through getToken().

5. Never use legacy Bluebird JWTs.

6. Do not treat isMember:false as proof
   that a Bluebird account does not exist.

7. Do not treat isAuthenticated:false as
   proof that registration is required.

8. Only enter the linked state when the backend
   provides authoritative identity confirmation.

9. If the backend cannot confirm the identity,
   preserve the existing Pending / Unlinked screen.

10. Do not automatically link users by phone number.

11. Do not create Bluebird accounts automatically.

12. Prepare navigation integration with the
    existing Registration, Onboarding and Home
    screens.

13. Do not rebuild existing screens.

14. Keep authenticated member-data access disabled
    until the backend contract is verified.

15. Add mocked tests for:
    - Existing member
    - Missing member
    - Onboarding required
    - Unauthorized session
    - Network failure
    - Backend failure
    - Account switching
    - Sign-out cache clearing

16. Run TypeScript and relevant tests.

IMPORTANT:

Do not make production API requests.
Do not modify production backend.
Do not create or link real accounts.
Do not send SMS.
Do not deploy.

If the existing backend contract does not
provide authoritative identity resolution,
do not invent a successful member state.

Report the exact backend requirements
needed to activate the flow.
