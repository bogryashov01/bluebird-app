BLUEBIRD MOBILE — FLIGHT DETAILS DESIGN IMPLEMENTATION

PRIORITY: HIGH
MODE: BUILD / EXECUTE

GOAL:

Bring the existing Bluebird Mobile Flight Details
screen as close as possible to the approved
Bluebird App Prototype design.

REFERENCE:
https://bluebird-app-prototype.replit.app

The Main Bluebird passenger/API investigation
(Task #1677) is complete.

Use its confirmed findings.

SCOPE:
artifacts/bluebird ONLY.

==================================================
1. DESIGN
==================================================

Match the approved Flight Details design:

- Large aircraft hero image
- Back button
- Aircraft name
- Route badge
- Departure date and time
- Premium white background
- Rounded information cards
- Blue primary action button
- Consistent spacing and typography

Preserve existing navigation and API integration.

==================================================
2. REAL FLIGHT DATA
==================================================

Use existing GET /api/empty-legs/{id} integration.

Display only fields actually available
from the API.

Show:
- Aircraft type/model when available
- Origin and destination
- Departure information
- Flight duration when available
- Aircraft images when available

Do not invent missing values.

Do not display prices because the
current client API suppresses pricing.

Do not display "Seats Available" because
the API does not expose remaining seats.

==================================================
3. FLIGHT INFORMATION CARDS
==================================================

Remove unsupported information:

- Range
- Speed
- Unverified weather
- Unverified Wi-Fi
- Unverified pets policy
- Unverified baggage allowance

Replace these with useful verified
flight information.

Only display cards when their data exists.

Preserve the approved visual styling.

==================================================
4. FBO AND MAPS
==================================================

If the API returns authorized FBO information,
display it and allow opening the location
in a native map application.

If FBO information is unavailable,
display the departure airport instead.

Use actual airport information from
the existing airport API.

Never invent FBO addresses.

Never treat airport coordinates as
exact FBO coordinates.

Do not expose gated FBO information.

==================================================
5. PASSENGER SELECTION
==================================================

Do not implement a pre-queue passenger selector.

The Main Bluebird API does not support
passenger count during queue joining.

Passenger manifests are managed separately
for the winning member after queue close.

Do not create a misleading passenger
reservation interface.

Do not send passengerCount to queue APIs.

Preserve existing Queue safety gates.

==================================================
6. PRIMARY ACTION
==================================================

Keep the existing primary action styling.

Do not enable unverified queue mutations.

Do not simulate successful queue joining.

If the action is unavailable, show a clear
user-friendly unavailable state.

==================================================
7. SAFETY
==================================================

Do not modify:
- Main Bluebird Website
- Main API
- Database
- Clerk configuration
- Production environment
- EAS configuration

Do not rewrite authentication.

Do not modify unrelated Mobile screens.

==================================================
8. VERIFICATION
==================================================

Rebuild shared libraries.

Run Mobile TypeScript.

Run relevant Flight Details tests.

Verify:
- Discover → Flight Details navigation
- Back navigation
- Real flight information
- Missing-data states
- Maps interaction
- Queue safety gates

Visually compare against the prototype
at iPhone screen sizes.

==================================================
9. DELIVERY
==================================================

Implement changes directly.

Report:
- UI changes
- Files modified
- Data fields displayed
- Maps implementation
- Tests passed
- Remaining differences from prototype
